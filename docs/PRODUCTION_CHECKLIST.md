# AI動画制作のチェックリスト

## 企画
- [ ] 「誰が何を知りたい／見届けたいか」が一文で書ける。
- [ ] 冒頭で視聴者に何の疑問・期待を作るか決まっている。
- [ ] 最後の報酬（答え・オチ・完成・結果）を決めている。
- [ ] 途中で少なくとも一度、状況／問い／期待が進展する。
- [ ] テーマと構成の型を分けて選んだ。無条件に高速化しない。

## 台本
- [ ] 最初の発話は導入のあいさつではなく本題に入る。
- [ ] 一文が短く、次の文につながる理由が分かる。
- [ ] 数字には意味と比較対象がある。
- [ ] 「だから何？」への答えがある。
- [ ] 事実と比喩・仮説を混同していない。
- [ ] 長いナレーションなしでも映像の流れを追えるか確認する。

## 映像とテロップ
- [ ] 各カットの目的を一文で説明できる。
- [ ] 文字、図、実例の対応が一致している。
- [ ] 実際の書き出しフレームで字幕の折返しと重なりを確認した。
- [ ] スマホの小画面・Shorts UIの被りも考慮している。
- [ ] 目立つ要素が多過ぎず、視線の行き先が一つに定まる。
- [ ] 動く理由のないアニメーションを増やしていない。

## 音とテンポ
- [ ] 人の声を必要とする企画ではナレーションの可否を先に確認。
- [ ] BGM／効果音が説明を邪魔していない。
- [ ] 静止・無音の間も意味がある場合だけ残している。
- [ ] カット頻度は内容の理解と期待に合わせる。機械的な秒数ルールを作らない。

## 完成ゲート
- [ ] MP4として開ける。映像の寸法、長さ、音声トラックを確認した。
- [ ] 冒頭・途中・最後の実フレームを確認した。
- [ ] 全体を視聴して意味の破綻／字幕重複／不自然な沈黙を確認した（未実施なら記録）。
- [ ] 著作権や事実情報を確認した。
- [ ] 「技術的に正常な動画」と「見る価値のある動画」を分けて判断した。
- [ ] 動画を公開した場合、視聴者データで仮説を更新する。

**過去の失敗**：反応速度Shortsでは、最初は文字と図が乱れ、修正版では画面整理が進んでも「だから？」と感じられる構成だった。技術品質と企画品質を別々に検証する。
